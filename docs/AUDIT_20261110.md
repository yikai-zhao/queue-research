# Execution-markout ordering and evidence audit

2026-11-10; scope: public synthetic research code and its saved examples.

## Correctness problem

`BookEvent` is the **post-event** book. The original conservative and
cancellation-ahead simulations could treat an execution on the *same event*
used for a fixed-horizon markout as a historical fill. This is a zero-holding-
period artifact: the exit snapshot was also used to establish the entry.

The correct interval for a fill at index `j` is
`activation_index < j < markout_index`. The markout event itself cannot
retroactively establish an order fill. A regression test first failed against
the original code, then passed after restricting the fill scan to events
*strictly before* the markout. Partial fills before the horizon remain valid.
The `naive_touch` upper-bound comparator is deliberately unrealistic and is
not presented as an execution model.

## Reproduced evidence drift

After the earlier session-boundary, latency, and walk-forward changes, the
previously committed `synthetic-{null,predictive}-seed11.json` files no longer
matched `study()` output from the then-current source. The visible execution
fractions and the report schema had changed. Both reports and the aggregate
`robustness-seed11.json` were regenerated from `seed=11`, 16,000 synthetic
rows; the fixed 12-seed control panel was rerun and remained identical
(0/12 nominal null detections, 8/12 injected-positive detections).

The new `test_evidence_reproducibility.py` compares *all* fields of the saved
seed-11 reports against current calculations and checks SHA-256 manifests,
including newer walk-forward source/tests. After future changes, any stale
research output must trigger a failing test rather than silently remain in
`evidence/`.
